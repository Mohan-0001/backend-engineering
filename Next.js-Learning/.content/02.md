# Next.js App Router: Navigation, Images, and Fonts

> Practical notes for the **Next.js App Router** using TypeScript and
> the `src/app` directory. Examples use current App Router conventions;
> check the documentation for version-specific behavior.

## 1. Navigation in Next.js

Next.js provides navigation tools that work with its file-based routing
system. For normal links between pages in your own app, use `Link` from
`next/link`.

### 1.1 `Link` --- normal navigation

Suppose the app contains:

``` text
src/app/
├── page.tsx
├── about/
│   └── page.tsx
└── products/
    └── page.tsx
```

Use `Link` to navigate between these routes:

``` tsx
// src/app/page.tsx
import Link from "next/link";

export default function HomePage() {
  return (
    <main>
      <h1>Home</h1>
      <nav>
        <Link href="/about">About</Link>
        <Link href="/products">Products</Link>
      </nav>
    </main>
  );
}
```

**Why `Link`?**

-   It provides client-side navigation for internal routes.
-   Next.js can prefetch eligible route data and code to make navigation
    faster.
-   It works with the App Router's route and layout system.
-   It avoids a full document reload in the normal client-side
    navigation case.

Use a regular `<a href="https://example.com">` for external websites. A
regular anchor can also be appropriate when you deliberately want
standard browser navigation.

### 1.2 Dynamic routes with `Link`

Given this route:

``` text
src/app/products/[id]/page.tsx
```

Navigate to a particular product:

``` tsx
import Link from "next/link";

export default function ProductLinks() {
  const productId = "42";

  return (
    <Link href={`/products/${productId}`}>
      View product
    </Link>
  );
}
```

This link navigates to `/products/42`. The `[id]` folder defines a
dynamic route segment.

### 1.3 Programmatic navigation with `useRouter`

Use `useRouter` when navigation should happen in response to an action,
such as submitting a form. It is a Client Component hook.

``` tsx
"use client";

import { useRouter } from "next/navigation";

export default function SearchButton() {
  const router = useRouter();

  function openProducts() {
    router.push("/products");
  }

  return <button onClick={openProducts}>Browse products</button>;
}
```

Common methods:

-   `router.push(href)` --- navigate to a route and add a history entry.
-   `router.replace(href)` --- navigate without adding a new history
    entry.
-   `router.back()` --- go back in browser history.
-   `router.forward()` --- go forward in browser history.
-   `router.refresh()` --- request a refresh of the current route's
    Server Component payload. It does **not** automatically invalidate
    every server-side cache.

Do not import `useRouter` from `next/router` in the App Router. Use
`next/navigation`.

### 1.4 `redirect` --- redirect from server-side code

Use `redirect` when the logic should send the user somewhere else, such
as after checking a condition in a Server Component or Server Action.

``` tsx
import { redirect } from "next/navigation";

export default async function DashboardPage() {
  const isSignedIn = false; // Example only; use real server-side auth.

  if (!isSignedIn) {
    redirect("/login");
  }

  return <main>Dashboard</main>;
}
```

`redirect()` interrupts rendering by throwing a framework-handled
redirect signal. Avoid wrapping it in a broad `try/catch` that
accidentally swallows that signal. Authentication and authorization must
be enforced on the server, not just by hiding links in the UI.

### 1.5 Read the current route: `usePathname`

`usePathname` reads the current URL pathname in a Client Component.

``` tsx
"use client";

import { usePathname } from "next/navigation";

export default function CurrentPath() {
  const pathname = usePathname();

  return <p>Current path: {pathname}</p>;
}
```

For `/products/42`, the pathname is `/products/42`. It does not include
the query string.

### 1.6 Read query-string values: `useSearchParams`

For a URL such as `/products?category=books&page=2`, use
`useSearchParams` in a Client Component:

``` tsx
"use client";

import { useSearchParams } from "next/navigation";

export default function ProductFilters() {
  const searchParams = useSearchParams();
  const category = searchParams.get("category");
  const page = searchParams.get("page");

  return (
    <p>
      Category: {category ?? "all"}; page: {page ?? "1"}
    </p>
  );
}
```

`useSearchParams()` returns a read-only URL search-parameters interface.
On statically rendered routes, using it can require a nearby `Suspense`
boundary in production builds. For server-side page logic, the App
Router page can instead receive a `searchParams` prop; consult the API
docs for the exact type and behavior in your installed Next.js version.

### 1.7 Which navigation tool should I choose?

  -----------------------------------------------------------------------
  Need                                Recommended tool
  ----------------------------------- -----------------------------------
  A normal clickable internal link    `Link` from `next/link`

  Navigate after a button click or    `useRouter` from `next/navigation`
  client-side action                  

  Redirect from server-side route     `redirect` from `next/navigation`
  logic                               

  Read the current pathname in a      `usePathname`
  Client Component                    

  Read query-string values in a       `useSearchParams`
  Client Component                    

  Read dynamic route values           Route `params` in the page/layout,
                                      or the relevant navigation hooks
                                      where appropriate
  -----------------------------------------------------------------------

**Rule of thumb:** start with `Link`. Use programmatic navigation only
when navigation is a consequence of application logic.

## 2. Images with `next/image`

Next.js provides the `Image` component from `next/image`. It extends
normal image behavior with features such as image optimization,
responsive sizing support, and lazy loading by default for images that
are not high priority.

### 2.1 Local images

Place a static image in `public/`:

``` text
public/
└── team-photo.jpg
```

Then use it like this:

``` tsx
import Image from "next/image";

export default function AboutPage() {
  return (
    <Image
      src="/team-photo.jpg"
      alt="The team working together"
      width={1200}
      height={800}
    />
  );
}
```

Key points:

-   Files in `public/` are referenced from the site root, so use
    `/team-photo.jpg`, not `/public/team-photo.jpg`.
-   `alt` describes the image for accessibility and when the image
    cannot be displayed.
-   For this local-file form, provide `width` and `height` so Next.js
    can infer the aspect ratio and reserve layout space.
-   `width` and `height` describe intrinsic dimensions; CSS can control
    the rendered size.

You can also import a local image from the source tree. Static imports
let Next.js infer image dimensions:

``` tsx
import Image from "next/image";
import teamPhoto from "@/assets/team-photo.jpg";

export default function AboutPage() {
  return (
    <Image
      src={teamPhoto}
      alt="The team working together"
      style={{ width: "100%", height: "auto" }}
    />
  );
}
```

The `@/assets/...` path assumes your TypeScript path alias and file
location are configured to support it.

### 2.2 Responsive image sizing

For an image that should fill a container, use `fill` and give its
parent a positioned box with dimensions:

``` tsx
import Image from "next/image";

export default function HeroImage() {
  return (
    <div
      style={{
        position: "relative",
        width: "100%",
        aspectRatio: "16 / 9",
      }}
    >
      <Image
        src="/hero.jpg"
        alt="Mountains at sunrise"
        fill
        sizes="(max-width: 768px) 100vw, 50vw"
        style={{ objectFit: "cover" }}
      />
    </div>
  );
}
```

Understand the props:

-   `fill` makes the image fill its positioned parent.
-   The parent needs a meaningful size; otherwise the image may have no
    useful space to fill.
-   `objectFit: "cover"` fills the box while cropping overflow.
-   `sizes` tells the browser how wide the image is expected to appear
    at different viewport widths. This helps the browser choose an
    appropriate responsive source.

Use `width` and `height` for straightforward images with a known aspect
ratio. Use `fill` for images designed to occupy a container, such as
hero backgrounds or card thumbnails.

### 2.3 Remote images

For a remote image URL, configure the host in `next.config.ts` before
using it with `Image`.

``` ts
// next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "images.example.com",
        pathname: "/products/**",
      },
    ],
  },
};

export default nextConfig;
```

Then:

``` tsx
import Image from "next/image";

export default function RemoteProductImage() {
  return (
    <Image
      src="https://images.example.com/products/shoe.jpg"
      alt="Running shoe"
      width={640}
      height={480}
    />
  );
}
```

Use the actual image host and a narrow `remotePatterns` rule for your
app. Restart the development server after changing Next.js
configuration. Do not allow arbitrary remote hosts without a reason.

### 2.4 `priority` / `preload` and loading behavior

Images are lazy-loaded by default when appropriate. For a prominent
above-the-fold image, follow the API for your installed Next.js version:
newer versions provide a `preload` prop for images that should be loaded
early; older code may use `priority`. Avoid marking every image as high
priority because that can hurt performance.

``` tsx
<Image
  src="/hero.jpg"
  alt="A mountain landscape"
  width={1600}
  height={900}
  preload
/>
```

Use this only for a genuinely important, immediately visible image, and
confirm the prop supported by your Next.js version.

### 2.5 When should I use a regular `<img>`?

Prefer `next/image` for most application images when its optimization
and sizing features are useful. A plain `<img>` can still be appropriate
for cases where you intentionally do not want Next.js image optimization
or where another image delivery system manages the behavior. Follow the
requirements of your chosen image source and deployment environment.

## 3. Fonts with `next/font`

Next.js includes the `next/font` system to optimize font loading and
help avoid layout shifts. Fonts can be loaded locally or through
supported Google Fonts.

For many apps, define fonts in the root layout so the same font is used
throughout the application.

### 3.1 Google Fonts with `next/font/google`

Import a font from `next/font/google`, configure the weights and
subsets, and apply the generated class.

``` tsx
// src/app/layout.tsx
import type { Metadata } from "next";
import { Inter } from "next/font/google";
import "./globals.css";

const inter = Inter({
  subsets: ["latin"],
  variable: "--font-inter",
  display: "swap",
});

export const metadata: Metadata = {
  title: "My App",
  description: "My Next.js application",
};

export default function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <html lang="en">
      <body className={inter.className}>{children}</body>
    </html>
  );
}
```

What each part does:

-   `Inter` is the font function imported from `next/font/google`.
-   `subsets: ["latin"]` includes the Latin character subset used by the
    app. Choose subsets supported by the font and needed for your
    languages.
-   `display: "swap"` lets fallback text render while the font loads.
-   `inter.className` applies the generated font class to the body.
-   `variable: "--font-inter"` also defines a CSS variable you can use
    if you apply the variable class.

If using the CSS variable, apply `inter.variable` instead of---or
alongside---`inter.className`, then reference the variable in CSS. For
example:

``` tsx
<body className={inter.variable}>{children}</body>
```

``` css
/* globals.css */
body {
  font-family: var(--font-inter), Arial, sans-serif;
}
```

You can also configure weights when the font supports them:

``` tsx
import { Roboto } from "next/font/google";

const roboto = Roboto({
  subsets: ["latin"],
  weight: ["400", "700"],
  display: "swap",
});
```

Use only the weights and styles your design needs. Variable fonts may
support a `weight` range; check the specific font's supported
configuration.

### 3.2 Local fonts with `next/font/local`

Use `next/font/local` when you have font files in your own project or
are required to self-host the font.

Example structure:

``` text
src/
├── app/
│   └── layout.tsx
└── fonts/
    ├── Brand-Regular.woff2
    └── Brand-Bold.woff2
```

Load the files:

``` tsx
// src/app/layout.tsx
import localFont from "next/font/local";
import "./globals.css";

const brandFont = localFont({
  src: [
    {
      path: "../fonts/Brand-Regular.woff2",
      weight: "400",
      style: "normal",
    },
    {
      path: "../fonts/Brand-Bold.woff2",
      weight: "700",
      style: "normal",
    },
  ],
  variable: "--font-brand",
  display: "swap",
});

export default function RootLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <html lang="en">
      <body className={brandFont.variable}>{children}</body>
    </html>
  );
}
```

Then use it in CSS:

``` css
body {
  font-family: var(--font-brand), sans-serif;
}
```

The relative `path` is resolved from the file containing the `localFont`
declaration. Adjust it if your font files are stored elsewhere.

### 3.3 Why not just use a Google Fonts `<link>`?

Using `next/font/google` downloads the font files at build time and
self-hosts them with the app. This avoids making the visitor's browser
fetch the font directly from Google at runtime. It can also help control
font loading and layout stability.

Builds that use Google fonts need network access to fetch the font files
at build time. If your build environment is offline or you want fully
local control, use `next/font/local`.

## 4. Common mistakes to avoid

### Navigation

-   Importing `useRouter` from `next/router` instead of
    `next/navigation` in the App Router.
-   Using `useRouter`, `usePathname`, or `useSearchParams` in a Server
    Component. These are client-side hooks.
-   Using `router.push()` for every ordinary link instead of `Link`.
-   Assuming `router.refresh()` clears every cache.
-   Treating client-side route protection as sufficient authorization.

### Images

-   Using `/public/image.jpg` instead of `/image.jpg` for files inside
    `public/`.
-   Forgetting `alt` text.
-   Using `fill` without giving the parent a positioned size.
-   Forgetting `sizes` on responsive `fill` images.
-   Using a remote host without configuring `images.remotePatterns`.
-   Marking every image as a preload/high-priority image.

### Fonts

-   Loading many font families and weights unnecessarily.
-   Applying a CSS variable in CSS without adding the font's `variable`
    class to an ancestor.
-   Assuming `next/font/google` always works in an offline build
    environment.
-   Putting font declarations inside components that render repeatedly
    instead of defining shared fonts at module scope.
